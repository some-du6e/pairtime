# Erratum: the level of a reading second drained from side-door output

Date 2026-11-20. Raised by the WP-SC2 review fix-up (#80). Status: decided 2026-11-24 by the orchestrator for Karim: the rule below stands as `pkg/score` has run it since #52, and rule 3 also covers a queued message that a plugin reported, which `pkg/score` misses today (Decision, below). The `pkg/score` PR that fixes that takes a new MINOR (DESIGN 6.6), adds table tests for rules 3 and 4 and for the queued message, and names the message in DESIGN 6.4. DESIGN 6.4 and 5.2 and the evidence definition take the rule's text, under `oracle-change`, in that PR or in WP-ERR1's PR for [the two-tabs erratum](2026-11-19-sm-6.3-two-tabs.md) after #222, whichever lands first. No fixture depends on the rule: every side-door case in `testdata/timelines/sidedoor` credits the same seconds at the same levels either way, and no fixture has a queued message that a plugin reported.

## Input

- DESIGN 6.4: "A second credited from the reading bucket takes the level of the human anchor that qualifies the drain (the nearest one within `READ_HORIZON_S`)." And "A lookup takes the lower level of its two bracketing anchors."
- DESIGN 5.2 and 6.2 D2: output sizes reported by `via = plugin` or `bridge` events fill a session's reading bucket "only up to `R_TURN_BASE_S` = 20 s per turn, unless a hook or transcript record backs the turn".
- DESIGN 7.12: "Forged plugin output sizes, or bridge heartbeats with big line counts" earn "0 submittable", because of "Level C; the bucket fill is capped at `R_TURN_BASE_S`".
- SM 2.7 drains any session's bucket in the focused project, and SM 3.3 rule 4 takes the oldest entry first, across sessions.

## Expected

A second credited from what a side door reported is level C, as 7.12's "0 submittable" needs.

## What the rules give

The cap is per turn, and a side door can claim as many turns as it likes. Every `agent.output` whose `turn_key` no prompt carries becomes a turn of its own, as a stop-hook continuation does (`testdata/timelines/README.md`, Turns). So thirty plugin outputs under thirty turn keys, in a session of project P that no hook sees, put 30 × 20 s = 600 s in its bucket, while each turn's fill still reads 20 s.

DESIGN 6.4 then gives those seconds the level of the nearest anchor of P. If the person has a Claude Code session of P with hooks, its last prompt qualifies the drain, so the plugin's 600 s come out level A or B, named after that prompt, with no `via_plugin`. A lookup bracketed by them is level A or B too. Neither the level-C opt-in nor the `ai_logged_s / 3` cap applies to any of it.

## What the scorer does

1. Side-door output fills only a turn that a prompt opened. A turn that only a side door's turn key created gets no allowance (`turnFill.add` in `pkg/score/bucket.go`).
2. A second drained from side-door output takes level C, lower than the anchor that qualifies the drain, and carries the side door's label (`via_plugin` or `via_bridge`). The anchor still qualifies the drain and is named in the second's `anchor_ids`.
3. A second drained from the base of a turn that a side-door act opened (a plugin or bridge prompt, or a `pairtime track` call) takes no better than that act's own level, and carries its label. So FX4 (b)'s track bases stay level A, as its keyboard evidence makes them, and (a)'s stay level C.
4. A lookup takes the lower level of its two brackets as they were credited, so a bracket drained from side-door output passes on its level C and its label.

## Decision

Item 1: the rule stands as `pkg/score` has run it since #52, in every release, and rule 3 also covers a queued message that a plugin reported. Item 2: yes. The sentences go in DESIGN 6.4's levels paragraph, whose lookup sentence changes to match rule 4, and DESIGN 5.2's cap bullet says what rule 1 adds.

An output size that a plugin or the bridge reports has only the side door behind it. Key presses before a prompt show that a person sent the prompt, not how much the agent showed, so a second drained from that output is level C whatever anchor qualifies the drain (rule 2). The base a side-door act starts its turn with is that act's own allowance, so it drains no better than the act, which is level C, or level A where key presses corroborate the act (rule 3). A lookup takes the levels its brackets were credited at, so a browser run next to such a second can't lift it back to A or B (rule 4). Rule 1 keeps a side door from multiplying the per-turn cap with turn keys of its own, and it costs only side-door continuation turns, whose reading would be level C anyway.

So unless key presses corroborate its acts, a pump earns only level C, which never reaches public totals, build days or boards (D11). A submission takes it only under a program's level-C opt-in, inside forge-verified commit intervals and within `ai_logged_s` / 3 (D5). Plugin records never count toward `ai_logged_s` (D19), so a plugin pump earns 0 submittable seconds, as DESIGN 7.12 says, unless other AI-logged time leaves room under that third. Bridge records from heartbeats that passed the peer-process check do count, so a bridge pump whose heartbeats pass it raises that third itself. DESIGN 7.12's bridge row doesn't say so, and this decision leaves 7.12 as it is.

Item 1's alternative caps `R_TURN_BASE_S` per session between human prompts. A plugin can name session keys as freely as turn keys, so that cap multiplies the same way, and what got through would keep a hook anchor's level A or B, which public totals and build days count.

Rule 3 covers every base a side-door act starts. `pkg/score` applies it to a `pairtime track` call and to a plugin or bridge prompt, but a queued message that only a plugin reported resets its session's bucket to a base with no side-door source, so that base drains at the level of whatever anchor qualifies the drain. That is a gap in the code, not in the rule, and the fix gives that reset the queued message's own level and label, as a prompt's reset has.

Not changed by this decision:

- Side-door output still fills an automated turn that a side-door prompt opened, up to `R_TURN_BASE_S`, so scheduled prompts can fill a bucket with level-C reading up to `BUCKET_MAX_S`. Under SM 3.3 rule 4 those entries drain before a hook session's newer output, which then drains later or not at all. That moves seconds from level A or B to C, never the other way.
- Which side-door output reaches a bucket. `pkg/score` drops all side-door output of a session that a hook or log record reports, even output from before that record. Whether that should follow the records as they arrive is the side-door-hindsight erratum's question, which WP-ADE1's next PR adds. Under either answer, side-door output that reaches a bucket follows rules 1 to 4.
- SM 2.5 says nothing credited from a session that no hook or log reader sees can be the credited slot a browser run starts after ([the turns-without-a-stop erratum](2026-11-19-turns-without-a-stop.md)), so a second drained from side-door output can bracket a lookup only after the run. `pkg/score` doesn't apply that bullet yet, and until it does such a second can open a lookup too, at level C under rule 4.
- Rule 3 holds whatever level the act has. D-macos-hid-posted rewrites its last sentence in the PR that moves FX4 (b)'s track calls to level C and adds case (h).
- DESIGN 6.4's level table. Its rows give an anchor's level. The new sentences only put a second below the level of the anchor that qualifies it, and they say so, which leaves every row as it is.
