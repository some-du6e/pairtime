## Decision

SM 6.1 changes to the replay, under two clarified rules that keep its `ai_logged_s` and `ai_ratio`.

- **The split.** SM 5.4 gives each gap to the record that ends it, as Hackatime's category breakdown does (HC 1.4). `ai_logged_s` is the part of `logged_s` in gaps that end at agent events, and `coding_logged_s` is the gaps that end at other editor heartbeats. An editor heartbeat within 5 s of an agent edit of the same file counts as part of that edit, as wakatime-cli treats it (HC 2.2). Records of the same millisecond go in `seq` order. So the first prompt, at 14:04:00, takes its 120 s from the 14:01:50 heartbeat like every other prompt, each cycle has 270 s, and the total is 4,050. The table above reads the agent events as a series of their own, which is why it gives 3,930.
- **Item 2: yes.** SM 5.3 counts a window's first record's gap from the last counted record before the window, as Hackatime's boundary-aware path does and DESIGN D15 already does for `hackatime_logged_s`, so consecutive devlog windows add up. Here that record is the 13:57:05 heartbeat. Its 205 s gap to the 14:00:30 heartbeat counts 120 s, as `coding`.
