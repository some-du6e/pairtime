# Erratum: SM's rules don't decide 6.6's uncredited codes

Date 2026-11-19. Raised by WP-FX1. Status: decided 2026-11-20 by the orchestrator for Karim. SM 5.2 now orders the uncredited codes: withheld-credit codes come first, and only on seconds a rule would have credited; then X.absent, X.other_focus and X.ambiguous; then X.agent_only, X.automated or X.no_input while a turn of the slot's focus project runs; then X.no_anchor. SM 2.5 gives a slot the window held longest in it, where os.focus records with the same app_class and focus_project are one window, and the hosted set that window held longest. SM 3.2 and DESIGN 3.3 walk the focused window's process tree again when a session starts or ends under it. A terminal hosting no harness stays X.ambiguous, and testdata/timelines/6.6's rows now have seconds.

## Input

SM 6.6, Casey's `claude -p` loop with a mouse jiggler on a Windows laptop without the key counter. The table credits 0 s in every minute and lists these uncredited codes, without seconds:

| Minute | What happens | Codes |
|---|---|---|
| 22:00 | `claude -p` starts at 22:00:05; origin `headless` | `X.automated` |
| 22:01 | The agent edits two files | `X.agent_only` |
| 22:02 | The agent stops at 22:02:10; the script sleeps 167 s | `X.agent_only`, `X.no_anchor` |

## Expected

A minute bucket holds uncredited seconds by code (SM 5.1), so the fixture needs each minute's split, and SM's rules should decide it.

## What the rules give

1. **Which seconds are `X.automated`.** SM 5.2 defines it as "The turn's origin was `scheduled`, `self_continue`, `subagent`, `headless` or `cloud`", but no rule says which seconds carry the code. One headless turn runs from 22:00:05 to 22:02:10, yet the table calls its first minute `X.automated` and the next two `X.agent_only`. SM 6.4 uses the code differently again: its overnight row says "turns `X.automated`" while every second there is `X.absent`. As a code for the seconds an automated turn runs while the person is present and focused, 22:01 and 22:02 would be `X.automated` too. As a code that never beats `X.agent_only`, 22:00 and 22:05 would be `X.agent_only`.
2. **The terminal between runs.** Once `claude -p` exits, Windows Terminal hosts no harness process. SM 3.2 resolves such a terminal "through the shell hook's reported `cwd` when that is installed (v1.5), else `ambiguous`". The v1 client has no shell hook, so the jiggler's seconds between runs are `X.ambiguous`, not `X.no_anchor`. SM 5.2's own example, "a jiggler on an open terminal ends up here", is still right for a terminal that hosts an idle session, with no turn running; during each run the turn step makes those seconds `X.automated`. The same applies to 22:00:00 to 22:00:05, before the first `claude` starts.
3. **Minutes with no bucket.** In 22:03, 22:04 and every later minute in which the script only sleeps, nothing is credited and no agent runs, so SM 5.1 writes no bucket and no upload reports their codes. The table's `X.no_anchor` for 22:03 to 22:04 describes the person's state, not a bucket.

## What the fixture does

Its rows give credited seconds (0), `agent_running_s`, which minutes have a bucket, and now each bucket minute's uncredited seconds by code. gen.py computes every second's code from the events with SM 5.2's order and SM 2.5's slot focus, and checks the rows against SM 6.6's. No row names this erratum any more, and scorer tests check the seconds like any other row's.

The fixture's `os.focus` events say what the terminal hosts: the agent records the focused window again when a session starts or ends under it, so between runs its `hosted_sessions` is empty. That follows SM 3.2 and is what makes point 2 visible.

## A rule to decide it

For a second that nothing credits, take the first that applies:

1. `X.absent`: no presence, a lock or sleep.
2. `X.other_focus`: input to an app outside every project.
3. `X.ambiguous`: focus that can't be resolved to one project (SM 3.2).
4. The focused project has an agent turn running: `X.automated` if the turn's origin is automated, `X.agent_only` if a person started it.
5. `X.no_anchor`: anything else.

Discount codes (SM 4.2) and `X.no_input` stay where SM puts them, on the seconds a discounted or no-input turn's windows would have credited.

Under this rule, 6.6 reads: 22:00 `X.no_anchor` 5, `X.automated` 55; 22:01 `X.automated` 60; 22:02 `X.automated` 10, `X.no_anchor` 5, `X.ambiguous` 45; no bucket for 22:03 and 22:04; 22:05 `X.no_anchor` 2, `X.automated` 58, because focus is decided per 15 s slot; and the same pattern for the 47 later iterations. SM 6.1 to 6.4 keep their numbers, since the cap codes rank first; 6.5's loop codes follow the loop-codes decision. Their `X.agent_only` seconds fall in turns a person started, and their `X.absent` seconds have no presence. `agent_only_s` stays the agent's whole running time, whatever the per-second code.

## Decision

Decided 2026-11-20 by the orchestrator for Karim.

- **SM 5.2's order.** Each uncredited second carries one code. Codes for withheld credit come first, and only on seconds a rule would have credited: a loop's discount code where SM 4.2 counts the second as part of what the loop cost, then `X.lookup_cap`, `X.bucket_cap` and `X.day_cap`. `X.noprog` is the uncredited half of a half-weighted second. Every other second takes the first that applies of `X.absent`, `X.other_focus` and `X.ambiguous`; then, while a turn of the slot's focus project runs, `X.agent_only` if a person started one, else `X.automated`, else `X.no_input`; and last `X.no_anchor`. Where presence is unknown (lookback), the presence and focus codes are skipped and any running turn counts.
- **SM 2.5's slot rule.** A slot's focus is the window that held focus for the most time in it, all its stretches there added up, and on a tie the one in front first. `os.focus` records with the same `app_class` and `focus_project` are one window, since `app_hash` stays on the device. For a terminal or agent app whose `hosted_sessions` change during the slot without changing its project, the slot's hosted sessions, and the project of a window hosting several (SM 3.2 rule 1), come from the hosted set that window held longest, again the earliest on a tie.
- **The re-walk.** SM 3.2 and DESIGN 3.3 walk the focused window's process tree again whenever a harness session starts or ends under it, and write a new `os.focus` when its hosted set changes. The fixture's `os.focus` records already follow this.
- **Point 2.** A terminal hosting no harness is `X.ambiguous` (SM 3.2), with no sticky project.
- **Point 3.** Minutes in which the script only sleeps have no bucket (SM 5.1).

The last sentence of the rule in A rule to decide it, "Discount codes (SM 4.2) and `X.no_input` stay where SM puts them, on the seconds a discounted or no-input turn's windows would have credited", gives way. Discount codes go on the seconds SM 4.2 says a loop cost, and `X.no_input` on a no-input turn's run, in the turn step above. [The code-placement erratum](2026-11-20-uncredited-code-placement.md) takes up the cap codes and live slots whose presence is unknown.

`testdata/timelines/6.6`'s rows now have seconds: 22:00 `X.no_anchor` 5, `X.automated` 55; 22:01 `X.automated` 60; 22:02 `X.automated` 10, `X.no_anchor` 5, `X.ambiguous` 45; no bucket for 22:03 and 22:04; 22:05 `X.no_anchor` 2, `X.automated` 58; and 22:06 to 01:59 `X.automated` 5,392, `X.ambiguous` 2,550 and `X.no_anchor` 158. Credited 0 s and the agent's 5,731 s don't change.
