Date 2026-11-24. Raised by the orchestrator's plan for 2026-11-24, entry 11, once #286 kept WP-SV8's dashboard server-rendered. - PLAN gives `web/src/server/` to WP-SV9 (PLAN.md:814), WP-RV1 (:1009), WP-RV2 (:1017), WP-RV3 (:1025), WP-RV5 (:1041), WP-PG6 (:1065), WP-PG9 (:1113), WP-CA1 (:1129), WP-SV18 (:1299), WP-SV16 (:1332) and WP-RV6 (:1413), and `web/src/shared/seal/` to WP-SB7 (:961). WP-SV8's Touches line (:789) already says "the owner's dashboard is server-rendered, so there is no `web/src/server/dashboard/`" (#292).
- Every page `pairtimed` serves is `html/template` through `internal/server/pages`. `pages.go` gives them one CSP, `default-src 'none'` with the inline stylesheet's hash and no script, and other packages render through `pages.Site.WritePage` (`app.go`), as `/device` does. #286, merged as ef589cf0, gives the owner's dashboard alone one script by its hash with `connect-src 'self'`, keeps the page working without it, and runs its Playwright check in `rehearsal.yml` against `cmd/pairtimed/live_test.go`.
- `web/src/server/App.svelte` is still WP-UI0's placeholder, "Nothing to see here yet", and nothing embeds `web/dist/server/`.
- `server-image.yml` builds the deployed image from Go alone, with no build cache. `release.yml` runs npm only in a job of its own, since #45's review found npm build code on the runner that signs releases.
- `ConsentCard` and `ProfileChoice` fix the cards' words, and their buttons are `type="button"`, which `web/tests/consent.spec.ts` requires (:47). A card with no script answers through a form instead, so the server's cards need those rules in a form's terms.

## Options

1. Go templates for every server page, with a hand-written script named by its hash where a page needs one, and browser checks in `rehearsal.yml` against the live harness.
2. The Svelte UI in `web/src/server`, embedded in `pairtimed` under its CSP, with a Node job in `server-image.yml` and `restore-drill.yml` and a Playwright job against `pairtimed`.

## Decision

Option 1, as PLAN's ground rule 12 states it.

`pairtimed` renders every page with `html/template` through `internal/server/pages`. A script is a hand-written file embedded from `internal/server/pages` with no import and no HTML sink, inlined and named by its SHA-256 in that page's own CSP, and `connect-src 'self'` goes only on a page whose script fetches. Pages work with JavaScript off, except a revealed item's text, which WP-SB7's `reveal.js` opens in the browser by design (DESIGN 7.6). Raw HTML in teen-written text shows as text. A form never answers with a redirect to another origin. WP-PG6's consent page alone names one more origin in `form-action`, its client's redirect URI's, because Chromium checks that redirect against it. The server's consent and profile cards say `ConsentCard`'s and `ProfileChoice`'s fixed words, which a Go test reads from the two components, and answer through one form per answer, keeping the components' rules in a form's terms. `web/src/server/` goes, and `web/` keeps the local dashboard, its components, their gallery and the Playwright specs.

Why. The server's pages ran no script before #286, which showed that a live page needs only one script by its hash. A Vite build would need `script-src 'self'` and would put npm code into an image that is built from Go alone. The review page is where minors' decrypted prompts sit in the DOM under a reviewer's session, the worst place for a bundle nobody reads line by line. Server rendering also keeps the must-view gate on the server and lets the minute drawer use `pkg/score` itself. `go test` in `ci.yml` checks the real HTML of a Go page but would see only a placeholder of a Svelte one, and the live harness from #286 already runs Playwright against `pairtimed` in one job. The 15 MB budget is the client's, so it argues for neither. WP-SV9 is due with M3 on 12-11, and its pages need no script.
