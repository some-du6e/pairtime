# Erratum: DESIGN 4.4 and 3.10 don't cover the display name a sign-in now keeps

Date 2026-11-21. Raised by Karim in Slack on 2026-11-21, after signing in on the live server. Status: decided 2026-11-21 by the orchestrator for Karim (D-display-name). pairtimed asks HCA for the `profile` scope and keeps one display name, `given_name` or else `nickname`, with the sign-in's session row only, never in `users`, so the name goes when the session's row does. Applied to DESIGN 3.10 and 4.4 on 2026-11-21 by #160.

## Input

- Signed in at https://pairtime.karimeltaib.com, Karim's header showed their Slack ID after "Signed in as", and Karim asked for their name there.
- DESIGN 3.10, the Accounts row: pairtimed requests `openid email slack_id verification_status` explicitly because discovery doesn't list them (SP 3.1).
- DESIGN 4.4, the server's sessions row: "Web sign-in sessions: the SHA-256 of each session token; its sign-in, expiry and revocation times; when HCA last authenticated the person".
- HCA's `profile` is a community scope. It brings `name`, `given_name`, `family_name`, `nickname` and `updated_at` (SP 3.1), and HCA's discovery document lists it in `scopes_supported`. HCA puts these claims in the ID token as well as in userinfo, and sets `given_name` and `nickname` both to the identity's first name (`config/initializers/doorkeeper_openid_connect.rb` in hackclub/auth at 301f618).

## Expected

The header names the person who signed in. The pages that ask whether an account is yours still show an id that nobody can pick for themselves.

## What changes

- pairtimed asks for `openid email profile slack_id verification_status`.
- Each sign-in keeps one name: `given_name`, else `nickname`, else none. Runs of spaces and control characters become one space, formatting characters such as the bidirectional overrides are dropped, and at most 64 characters stay. `name` and `family_name` arrive in the same ID token, and pairtimed never stores them.
- The name lives in `sessions.display_name` (migration 0006), never in `users`. It goes with the session's row, a day after the session ends. When HCA turns an account ineligible, the names its sessions kept go at once, in the transaction that drops its email and Slack ID (DESIGN 8.2), so they don't wait out the row's last day.
- The header says "Signed in as <name>", and without a name it falls back to the Slack ID, or the HCA subject, as before. `/device`, its confirmation, relink and taken pages, and `/account/devices` name the account as "<name> (Slack ID <id>)", since the Slack ID is what the reader checks.
- Only pages served to the signed-in browser show the name. A public profile still never shows a real name (DESIGN 8.3).

## Proposed wording

DESIGN 4.4, the server's sessions row:

| Where | Data | Kept |
|---|---|---|
| Server | Web sign-in sessions: the SHA-256 of each session token; its sign-in, expiry and revocation times; when HCA last authenticated the person; the display name HCA sent at that sign-in (`given_name`, else `nickname`, at most 64 characters), which no account row copies | Until sign-out, or 30 days after sign-in at the latest; the row is deleted 1 day after the session ends |

DESIGN 3.10, the Accounts row: "requesting `openid email profile slack_id verification_status` by name, since discovery lists only `openid profile phone birthdate` (SP 3.1)".

## For Karim

The orchestrator decided this for you, so nothing waits on you here. The wording above goes into DESIGN 3.10 and 4.4 in a docs PR. The deploy waits until the hosting agent adds `profile` to HCA app 1535, because HCA turns away, on its own page, every sign-in that asks for a scope the app lacks.
